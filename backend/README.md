# Real Estate Platform API

Cloudflare Workers API built with TypeScript, Hono, and D1. This directory is backend-only and does not modify the sibling `web-mobile/` application.

## Setup

1. Install Node.js 20+ and run `npm install` in this directory.
2. `wrangler.toml` points to the deployed `khane-yab-platform` D1 database. For a separate account/environment, create a new D1 database with `npx wrangler d1 create YOUR_DATABASE_NAME` and replace the name/ID in the configuration before deploying.
3. Apply schema with `npx wrangler d1 migrations apply khane-yab-platform --local` for local development or add `--remote` for the configured remote database.
4. Copy `.dev.vars.example` to `.dev.vars` and set a long random `ADMIN_INGEST_TOKEN`.
5. Run `npm run dev`; validate with `npm test` and `npm run typecheck`.

Do not commit `.dev.vars`, API tokens, or real credentials. Public listing sources must only be used through officially permitted APIs, licensed exports, user-submitted links, or manual imports. This backend contains no crawler and does not bypass login, robots rules, anti-bot checks, or other access controls.

## Source registry and permission gate

Every ingestion path is declared in the `sources` table (migration `0005_sources_observations.sql`). A source is usable only when it is **enabled** and its **permission status is `approved`**; the gate fails closed with `403 SOURCE_NOT_FOUND`, `403 SOURCE_DISABLED`, or `403 PERMISSION_NOT_APPROVED`.

| Source id | Kind | Hosts | Purpose |
|---|---|---|---|
| `src-demo` | `demo` | – | Synthetic fixtures shipped with the repository. |
| `src-manual` | `manual` | – | Operator-supplied JSON payloads. |
| `src-user-link` | `user_link` | `divar.ir`, `sheypoor.com` | A listing page the user pasted. The platform reads one page, stores only the fields needed for matching, and always links back to the source. |

`GET /api/sources` returns the approved and enabled sources. `GET /api/sources/:id/permission` reports the authorization state of one source without exposing credentials.

## API contract

JSON responses use UTF-8. Errors have `{ "error": { "code": "...", "message": "..." } }`; validation errors may include a Zod `details` object. Prices are integer **tomans** throughout this API; ingestion adapters must convert source prices into tomans before import. The legacy `price` field remains the comparison value for backwards compatibility; optional `salePrice`, `monthlyRent`, and `deposit` fields represent the sale amount, monthly rental amount, and deposit independently. Migration `0004_separate_rental_prices.sql` backfills existing sales/rentals from `price`; historical deposits remain unknown. Search preferences use anonymous UUIDv4 capabilities generated by clients: IDs are insert-only and there is no preference GET route. A preference expires after `PREFERENCE_TTL_HOURS` (default 24 hours) and is removed by the maintenance endpoint. This is suitable only for non-sensitive search sessions, not private profiles or durable saved preferences.

| Method and path | Purpose |
| --- | --- |
| `GET /health` | Health check |
| `GET /api/sources` | Approved and enabled data sources |
| `GET /api/sources/:id/permission` | Authorization state of one source |
| `PUT /api/preferences/:id` | Create anonymous search preferences using an unused UUIDv4 capability; repeated IDs return `409` |
| `GET /api/listings` | Filter active, fresh listings |
| `POST /api/recommendations/:preferenceId` | Return ranked listings with score and Persian explanation reasons |
| `POST /api/listings/import-link` | Import one listing page the user submitted (bounded fetch, allowlisted host) |
| `DELETE /api/listings/:id` | Withdraw a listing, or purge it with `?purge=true`; requires the admin token |
| `POST /api/ingest/manual` | Import up to 100 caller-provided listings; requires `Authorization: Bearer <ADMIN_INGEST_TOKEN>` |
| `POST /api/ingest/demo` | Import built-in sample listings; requires the same admin token |
| `GET /api/ingest/runs` | Recent ingestion runs (admin token) |
| `GET /api/ingest/runs/:id` | One run with its row-level diagnostics (admin token) |
| `POST /api/maintenance/cleanup` | Remove expired preferences, old observations, and stale rate-limit buckets (admin token) |

### Preferences JSON

```json
{
  "budgetMin": 3000000000,
  "budgetMax": 8000000000,
  "propertyTypes": ["apartment"],
  "transactionType": "buy",
  "city": "تهران",
  "neighborhoods": ["صادقیه"],
  "minBedrooms": 2,
  "minAreaM2": 80,
  "mustHave": ["parking"],
  "avoid": ["basement"]
}
```

All preference fields are optional; lists default to empty and `transactionType` defaults to `buy`. `budgetMin` cannot exceed `budgetMax`.

### Listing import JSON

`POST /api/ingest/manual` accepts `{ "listings": [ ... ] }`. Each listing requires `source`, `title`, `city`, `propertyType`, `transactionType` (`buy` or `rent`), and non-negative `price`. Optional fields include `sourceListingId`, HTTPS `sourceUrl`, `description`, `neighborhood`, `address`, `areaM2`, `bedrooms`, `bathrooms`, coordinates, `features`, and ISO datetime `publishedAt`. Invalid rows are counted as skipped, recorded in `import_errors` with the offending field names only, and reported as accepted, rejected, and duplicate counts.

### User-submitted link

`POST /api/listings/import-link` accepts `{ "url": "https://www.sheypoor.com/v/…" }`.

- The host must be inside the source allowlist; only `https` is accepted, credentials and non-standard ports are rejected, and literal IP hosts are refused.
- The worker follows at most three redirects and rejects any redirect that leaves the allowlist.
- The response body is read with a 512 KiB cap and an 8 second timeout; only `text/html` is accepted.
- Structured data (`schema.org` JSON-LD `Offer`) is read first, then OpenGraph metadata, then plain-text heuristics. Unknown fields stay unknown instead of becoming zero.
- The original page URL is always stored so the user can open the source listing, and every sighting is recorded in `listing_observations`.
- The route has its own hourly budget (`LINK_IMPORT_PER_HOUR`, default 20) in addition to the general per-minute limit.

### Search filters

`GET /api/listings?q=...&city=...&transactionType=buy&propertyType=apartment&minPrice=...&maxPrice=...&minAreaM2=...&minBedrooms=...&limit=20&offset=0`. Limits are clamped by validation (`limit` 1–100, `offset` 0–10000). The response also carries `total` and `hasMore`. Freshness defaults to 90 days, configurable with `MAX_LISTING_AGE_DAYS`.

### Scoring

Scores are normalized to 0–100 using only preference dimensions supplied by the user: transaction type (24), city (18), neighborhood (12), property type (10), budget (16), bedrooms (8), area (6), must-have features (6), and avoiding unwanted terms (20). Since the score is normalized by the sum of enabled dimensions, users can omit any dimension. Every result carries stable reason codes — `TRANSACTION_MATCH`, `LOCATION_MATCH`, `NEIGHBORHOOD_MATCH`, `PROPERTY_TYPE_MATCH`, `WITHIN_BUDGET`, `ROOMS_MATCH`, `AREA_MATCH`, `FEATURES_MATCH`, `PREFERENCE_MATCH`, `MISSING_KEY_FIELDS`, `STALE_LISTING` — together with a Persian label for each code, so a client can localize the wording without an API change. Freshness is exposed separately and used as a tie-breaker, followed by the listing id so the order is deterministic. `maxCommuteMinutes` is stored for contract stability but has no effect until reliable travel-time data is configured.

### Stale records

Listings older than `MAX_LISTING_AGE_DAYS` (default 90) are no longer hidden. They are returned with `stale: true`, a `freshnessScore` of 0, and the `STALE_LISTING` reason, and the clients label them «قدیمی». A stale record is a listing that has not been observed recently; it is never presented as confirmed available.

## Operational notes

- Every response carries an `X-Request-Id` header, and every error envelope carries the same value in `error.requestId`, so a user report can be correlated with the server log. The identifier is the Cloudflare Ray id when the edge supplies one.
- The operator routes (`/api/ingest/*`, `/api/maintenance/cleanup`, `DELETE /api/listings/:id`) require `Authorization: Bearer <ADMIN_INGEST_TOKEN>`. Configure it as a Cloudflare Worker secret (`npx wrangler secret put ADMIN_INGEST_TOKEN`); never commit it. The local value is kept in `backend/.admin-token.local`, which the repository ignores.
- CORS uses the comma-separated `ALLOWED_ORIGINS` environment variable. Set it to the exact production frontend origins before deployment; do not use `*` for a production deployment.
- Rate limiting uses an atomic D1 upsert keyed by Cloudflare's client IP header and opportunistically removes old buckets. The same configured per-minute limit currently applies to public and admin routes; this is a basic service limit, not a substitute for stricter admin-specific limits or edge controls under high traffic.
- Manual import bodies are limited to 1 MiB, preference bodies to 16 KiB, and link-import bodies to 8 KiB. Import URLs must use HTTPS. Public listing responses omit internal content hashes and precise street/coordinate fields.
- Duplicate detection uses `(source, source_listing_id)` where supplied, otherwise a SHA-256 fingerprint of normalized listing attributes. Similar listings with changed prices or titles may need a future review queue for fuzzy matching.
- `last_seen_at` is refreshed when a listing is seen again. Freshness filtering uses that timestamp.
- Before offering accounts or durable/private saved profiles, add user authentication and ownership authorization. The current anonymous capability flow is intended only for non-sensitive, short-lived search sessions; also configure exact CORS origins and review applicable privacy/retention requirements.

## Tests

`npm test` runs the Vitest suite: unit coverage of normalization, hashing, freshness, validation, scoring and hard constraints, plus route-level integration coverage against an in-memory D1 double (`test/fakeD1.ts`) that exercises the preference capability, the recommendations envelope, the user-submitted link flow, the SSRF and host allowlist rules, the permission gate, row-level import diagnostics, and the maintenance cleanup.
